# OpenPrintShare 使用指南（USAGE）

本指南面向普通用户，覆盖 **Host（共享打印机的一侧）** 与 **Client（发起打印的一侧）** 的完整使用流程。

> **能力真实性声明**：不同打印机提供的能力不同（墨量、双面、彩色、纸盒、分辨率等）。
> **OpenPrintShare 只显示实际读取到的数据**——读取到的能力标注为 `SUPPORTED`（支持）；
> 明确确认设备不支持的标注为 `UNSUPPORTED`（不支持）；读取不到的标注为 `UNKNOWN`（未知，
> 不代表不支持）。UI 不会显示任何猜测或写死的数值（例如墨量读取不到时直接不显示墨量模块）。

## 一、Host 使用流程

Host 是**连接打印机的那台设备**（如办公室的 PC / Mac / 服务器）。它把系统里已安装的打印机共享给局域网。

### 1. 安装

从 [GitHub Releases](https://github.com/wanan-love/ops/releases) 下载对应平台的产物：

| 平台 | 下载文件 | 安装方式 |
|---|---|---|
| Windows | `OpenPrintShare-Windows-x64-<版本>.exe` / `.msi` | 双击安装（msi）或直接运行 exe |
| macOS | `OpenPrintShare-macOS-arm64-<版本>.dmg` | 打开 dmg，拖入应用程序；首次启动如遇 Gatekeeper 提示，右键图标 →「打开」 |
| Linux | `OpenPrintShare-Linux-x64-<版本>.AppImage` / `.deb` | AppImage 直接运行（`chmod +x` 后双击）；.deb 用包管理器安装 |

- **无需安装 Node.js / Python / Rust / Java**：运行时已随程序打包。
- Linux/macOS 的 **CUPS 为系统自带组件**，无需额外安装；若宿主缺少打印组件，控制台「打印后端」页会给出明确说明。

### 2. 启动

- **Windows**：双击 exe（或安装后从开始菜单启动）。
- **macOS / Linux**：双击 AppImage / .app。
- 启动后自动打开浏览器（或手动访问 **`http://localhost:3001/`**）即可看到 Web 控制台。

命令行参数（可选，所有平台一致）：

```bash
openprintshare [--port 3001] [--ws-port 3002] [--data-dir <目录>] [--web <目录>] [--dev] [--version]
```

> **运行模式（v0.4.3 起产品红线）**：正式产物默认以**正式模式**运行——只包含真实打印后端
> （Windows 打印栈 / CUPS / IPP 直连），**不包含任何虚拟打印机或仿真设备**；启动时与每 60 秒
> 自动同步一次系统真实打印机（也可在「打印后端」页手动点「同步系统打印机」）。
> 开发/测试模式（`--dev` 或 `OPS_DEV_MODE=1`）才会启用虚拟打印机与 Virtual IPP/Scanner/PJL
> 仿真设备，且仅限开发调试用途——正式部署不需要也不应该开启。
> 平台信息由**运行时多信号动态检测**（概览页可见信号链），不使用开发/编译环境固定值。

### 3. 添加 / 发现打印机

控制台左侧「**打印后端**」页提供三种方式接入真实打印机：

1. **mDNS 扫描（推荐）**：点击「扫描 _ipp._tcp」，自动发现局域网中支持 IPP 的网络打印机（含 IPP Everywhere / AirPrint 机型），点「添加」即可。
2. **手动 URI**：已知打印机地址时填写 IPP URI（如 `ipp://192.168.1.50/ipp/print`），点「添加并探测」。
3. **系统打印机（CUPS / Windows）**：
   - macOS / Linux：Host 会读取 CUPS 队列（`lpstat` 枚举含系统默认队列 + `ipp://localhost:631` 能力探测）；
   - Windows：Host 通过 `Win32_Printer` 枚举系统已安装的真实打印机（名称/默认/状态/驱动/端口；
     状态含 `DetectedErrorState` 官方错误码：无纸/卡纸/门开/离线等）。
   - 系统打印机由 Host **自动发现并导入**（启动即同步 + 每 60 秒周期同步，幂等去重），无需手动操作；
     也可在「打印后端」页点「同步系统打印机」立即触发。导入后的卡片会带「系统默认」徽章（如系统设有默认打印机）。

添加成功后，打印机会出现在「打印机」页，并**自动完成一次真实能力探测**（IPP Get-Printer-Attributes + SNMP 耗材探测，多来源并行）。

### 4. 选择共享打印机

「**打印机**」页每张打印机卡片有「共享」开关。**打开开关的打印机会出现在所有客户端的打印页**；关闭则对客户端隐藏。卡片上同时显示：

- 打印机状态（在线 / 繁忙 / 离线 / 缺纸 / 卡纸 / 错误）
- 后端类型徽章（IPP 直连 / CUPS / Windows / Mock·Virtual）
- 能力报告（点开「能力报告」可查看每项能力的三态、数据来源与读取时间）
- 耗材（仅当设备真实返回墨量数据时显示）

### 5. 配置

- **安全模式（设备配对轴）**：「设备配对」页可切换：
  - **开放模式（默认）**：局域网内任何设备可直接连接（适合家庭/受信网络）；
  - **配对模式**：新设备需提交配对请求，Host 审批后颁发设备令牌（适合办公室/半公开网络）。
- **控制台访问控制（管理面轴，v0.4.0）**：「设备配对」页「控制台访问控制」卡片：
  - **启用**：生成 `ops_` 前缀访问令牌（192-bit 随机），此后 REST 管理接口与实时通道（WebSocket）需要令牌；设备打印 / 配对流程不受影响；协议仿真端口（Virtual IPP :3061 / eSCL :3065）保持开放以兼容真实打印机/扫描仪客户端；
  - **令牌传递**（三通道等价）：`x-ops-console-token` 请求头 / `Authorization: Bearer <token>` / URL `?opsToken=`（供 `<img>` 图片与文件下载链接使用）；
  - **锁定保护范围**：除公网白名单（`/healthz`、`/api/system/info` 探活、`/api/console/auth` 登录校验、`/api/console/enable` 收紧操作、设备配对发起、`POST /api/jobs` 打印提交）外的全部管理接口；
  - **防锁定**：启用与重生成时令牌同步落盘 Host 数据目录 `console-token.txt`（权限 0600），遗忘时可在 Host 本机读取恢复；
  - **关闭 / 重新生成**：需要持有效令牌（收紧永远开放、放开需要证明）；重生成后旧令牌立即失效，已连接的 WebSocket 会被服务端断开并要求重新握手；
  - **浏览器端体验**：Web 控制台未持有效令牌时自动弹出「控制台已锁定」解锁界面（输入令牌 → 校验 → 保存在本端 localStorage → 自动恢复）；令牌失效（如他端重生成）时界面会自动回到解锁态。
- **两轴模型**：控制台鉴权（管理面）与设备配对（打印面）相互独立、可叠加。生产环境建议双开。
- **PJL 探测（RAW 9100 双向回读，v0.4.2）**：「设备配对」页「PJL 探测设置（RAW 9100）」卡片：
  - **默认关闭**（安全默认：避免与在用打印通道互扰），启用后「刷新能力」时向打印机 RAW 端口发送 UEL 包裹的 `@PJL INFO STATUS / SUPPLY` 查询（超时 900ms，失败仅记探测记录）；
  - **适用场景**：Brother / HP 等品牌的消费级机型 SNMP 常缺失/禁用，但 RAW 9100（HP JetDirect 1992 年发明、事实上的打印通用端口）是双向字节流，可回读状态（CODE 10001 就绪 / 10002 离线 / 10004 打印中 / 40014 缺纸 / 40019 卡纸 / 40017 门开）与耗材（碳粉百分比）；
  - **端口**：真实设备通用 9100（默认），测试环境可指向 Virtual PJL Printer（:3067）；
  - **通道优先级**：IPP → SNMP → PJL（仅在前面来源未读到时补充）；未知 CODE 不映射状态（三态原则：不猜测）；
  - **如实声明**：`@PJL INFO STATUS` 为 HP PJL 参考手册标准；`@PJL INFO SUPPLY` 为 Brother 风格试点格式（公开资料未完全标准化），真实机型响应需抓包适配。
- **Host 名称**：在「概览」页展示主机名 / Host ID / 版本 / 平台 / 运行时长，供客户端确认连接目标。

### 6. 查看状态

「**概览**」页实时显示：共享打印机数、进行中任务、已完成任务、数据目录占用；打印机卡片实时同步状态（WebSocket 推送，断线自动轮询兜底）。

### 7. 管理设备

「**设备配对**」页：
- **配对模式**下审批/拒绝客户端的配对请求，查看已配对设备（设备名 / 令牌 / 最后活跃时间），可移除设备；
- **开放模式**下查看当前连接的设备。

### 8. 查看打印任务

「**打印队列**」页：全部任务实时列表（状态筛选 / 打印机筛选 / 只看本设备），点任意任务打开详情抽屉：
- 任务信息（文件名、页数、份数、提交设备、时间）
- 打印参数（纸型、色彩、单双面、质量）
- **状态时间线**（每个里程碑：排队 → 提交后端 → 打印中 25%/50%/75% → 完成）
- 结果（失败原因 / 完成工件）
- 操作：取消（打印中）、重试（失败/已取消）

## 二、Client 使用流程

Client 是**要打印文件的那台设备**（手机 / 平板 / 笔记本）。**客户端无需安装任何厂商驱动。**

### 1. 安装

- **浏览器（任何平台）**：无需安装。在局域网内任一设备打开浏览器即可（Web 控制台既是 Host 控制台也是 Client）。
- **Android**：安装 `OpenPrintShare-Android-arm64-<版本>.apk`（GitHub Releases 下载），打开后输入 Host 地址连接。
- **iOS / iPadOS**：Xcode 构建安装（TestFlight / App Store 分发，见 `clients/ios`）。

### 2. 发现 Host

控制台「**发现主机**」页：
- 自动扫描局域网（UDP Beacon），列出可用的 Host（主机名 / 地址 / 版本）；
- 自动扫描未发现时可**手动添加**：输入 Host 的 IP 和端口（默认 `3001`）。
- 连接成功后，顶栏显示「已连接 <主机名>」。

### 3. 配对

若 Host 开启了**配对模式**：
1. Client 首次连接时在「设备配对」页提交配对请求（含设备名）；
2. **Host 侧**「设备配对」页会出现待审批请求，点击「批准」；
3. Client 自动领取设备令牌，后续请求自动携带（无需人工干预）。

开放模式下此步自动跳过。

### 4. 发现打印机

连接 Host 后，「**打印**」页的打印机下拉列表即显示**所有共享中的打印机**（实时同步，Host 共享开关变化即时反映）。

### 5. 选择打印机

打印页选择打印机时，选择器会标注每台打印机的**后端类型**（如「IPP」），选择后显示该打印机的能力提示（如耗材未知时不显示墨量，避免误导）。

### 6. 选择文件

「**打印**」页：
- **拖放 PDF** 到拖放区，或点击选择文件；
- 无文件时可点「使用示例文档」快速体验。

> 当前版本支持 **PDF** 打印。其它格式建议先导出/打印为 PDF 再提交。

### 7. 设置打印参数

按需设置（超出打印机能力的选项会被自动钳制到安全值）：

| 参数 | 可选值 |
|---|---|
| 纸型 | A4 / Letter / Legal / A3 …（按打印机能力） |
| 色彩 | 彩色 / 黑白（黑白机会被钳制为黑白） |
| 单双面 | 单面 / 双面长边 / 双面短边（无双面能力时钳制为单面） |
| 份数 | 1 – 上限（按打印机能力，默认 1–99） |
| 质量 | 草稿 / 标准 / 高 |

### 8. 提交打印

点击「提交打印」，任务立即入队，页面显示提交进度与结果。**打印链路**：

```
Client → Host(REST 提交) → 打印机后端(IPP 直连 / CUPS / Windows Print Spooler) → 真实打印机
```

### 9. 查看任务

「**打印队列**」页实时跟踪（WebSocket 推送进度里程碑）：排队 → 打印中（25% → 50% → 75% → 100%）→ 完成 / 失败。点开任务看完整时间线。

### 10. 取消任务

打印中/排队中的任务：队列页该任务行点「取消」按钮（移动端点卡片上的取消图标）。已送入打印机硬件缓冲的极末段无法撤回。

## 三、原生打印与 OpenPrintShare 的关系

OpenPrintShare **优先兼容操作系统原生打印能力**，何时用系统原生、何时用 OPS 自己的流程：

### 使用系统原生打印能力的场景

| 场景 | 说明 |
|---|---|
| **Host 侧共享系统打印机** | Host 调用 CUPS（macOS/Linux）或 Windows Print Spooler（Windows）把 PDF 交给**系统已安装的驱动**——驱动渲染、纸盒选择、双面逻辑全部由系统打印栈处理，OPS 不重新实现也不替换驱动 |
| **IPP Everywhere / AirPrint 机型** | 打印机本身支持 IPP Everywhere 时，Host（或 IPP 后端）直接用标准 IPP 协议提交，免厂商驱动（系统和 OPS 都走同一条标准通道） |
| **Android 客户端本地打印机** | Android 系统打印框架（Mopria）可直连支持的打印机时，可不经 OPS 直接用系统打印菜单 |
| **iOS / macOS AirPrint** | 系统发现 AirPrint 打印机时可直接用系统打印对话框，无需 OPS |

### 使用 OpenPrintShare 自己打印流程的场景

| 场景 | 说明 |
|---|---|
| **打印机只接在某一台设备上（USB 共享）** | 打印机通过 USB 接在 Host 设备上，其他设备**无法**用系统原生方式发现它 → 必须经 OPS：Client → 网络 → Host → 系统驱动 → 打印机 |
| **客户端不想装厂商驱动** | 任何设备通过 OPS 打印都只需提交 PDF，**驱动只在 Host 一处安装**（IPP Everywhere 机型连驱动都不需要） |
| **统一队列与状态管理** | 需要**跨设备统一打印队列**（排队/取消/进度/时间线/事件审计）时，OPS 提供系统打印对话框不具备的集中管理 |
| **手机/平板打印任意共享打印机** | 手机系统打印框架发现不了的打印机（如 Host 的 CUPS 队列），通过 OPS Web/原生客户端均可打印 |

> 简单判断：**打印机网络可达且支持 AirPrint/Mopria → 系统原生即可；打印机挂在别人电脑上或需要统一队列 → 用 OPS。**
> 两者不冲突，可以并存。

## 四、ipps://（TLS 加密打印）

### 1. 什么是 ipps://

`ipps://` 是 **IPP over HTTPS**（RFC 8011 的 TLS 传输绑定），与 `ipp://` 的关系等同于 `https://` 之于 `http://`：
同一条 IPP 协议链路（能力探测 → 提交打印 → 状态回读），但全程 TLS 加密。企业级打印机与新款家用机型普遍支持（mDNS 服务类型 `_ipps._tcp`）。加密与解密均在两端完成，中间网络设备只能看到密文。

### 2. OpenPrintShare 的证书策略（自签容忍 / TOFU）

- 局域网打印机的 TLS 证书绝大多数是**自签名证书**，无法通过公共 CA 校验；
- OpenPrintShare 客户端对这类证书**自动容忍**（Trust-On-First-Use 模式）——与 CUPS driverless（cups-filters）、sane-airscan 等开源生态的处理方式一致；
- 因此 ipps 通道是**有加密、无 CA 身份校验**：可防被动窃听，不能防主动冒充（伪造端点）。高安全网络（企业/涉密环境）应在添加 ipps 打印机前，通过打印机面板或管理页核对设备指纹（序列号 / 证书指纹）确认设备身份。

### 3. 怎么用

**无需任何额外配置**，添加打印机时直接填 `ipps://` 地址即可：

- 「打印后端」页手动 URI 填入如 `ipps://192.168.1.50/ipp/print`，点「添加并探测」；
- 或直接使用 mDNS 扫描结果中的 ipps 条目（URI 旁有 TLS 徽章）；
- 探测、提交、状态读取全部走加密通道，其余流程与 `ipp://` 完全一致。

### 4. 排查要点

| 检查项 | 处理 |
|---|---|
| 证书 / TLS 握手失败 | 确认填写的是打印机的 **ipps 端口**（常见 443 / 631，部分机型与 ipp 明文端口不同——地址在打印机网络配置页上） |
| 连接超时 | 防火墙放行对应 ipps 端口（TCP）；跨网段确认路由可达 |
| `ipp://` 正常但 `ipps://` 失败 | 部分老机型未开启 TLS——在打印机管理页面（EWS）开启 IPP over TLS / 安全 AirPrint 选项 |
| 添加成功但能力显示 UNKNOWN | 与 `ipp://` 行为一致（能力三态模型），见「故障排查 · 第 4 条」 |

### 5. 开发 / 测试环境说明

Virtual IPP Server（开发/测试工具）同时监听明文 **:3061**（ipp）与 TLS **:3063**（ipps，自签证书）两个端口，可在无实体打印机的 CI/开发环境中验证 ipps 全链路（自动化自测场景 `ipps-full-flow`）。

## 五、扫描（eSCL）

### 1. 什么是 eSCL

eSCL（又称 AirScan）是 **HTTP + XML 形态的标准扫描协议**，Apple AirPrint 认证的多功能一体机（MFP）普遍支持，与 sane-airscan / AirScan 开源生态兼容。支持 eSCL 的扫描仪通过 mDNS 服务类型 **`_uscan._tcp`** 在局域网通告自己——OpenPrintShare 可**自动发现**，也支持**手动添加**。

### 2. 使用流程

控制台「**扫描**」页：

1. **选设备**：自动发现的设备带「发现」徽章，手动添加的带「手动」徽章；
2. **设参数**：分辨率（75–1200 dpi）、色彩（彩色 / 灰度）、输稿器（平板 / 送稿器）、**双面扫描（v0.4.1，仅送稿器）**；设备列表带双面能力徽章（「双面」= 已声明支持 / 「双面?」= 未探测到声明，不代表不支持）；
3. **开始扫描**：任务实时推送进度（扫描中 → 已完成 / 失败 / 已取消）；
4. **预览 / 下载**：完成后页面内直接预览（PNG），可逐页浏览、下载任意页；**送稿器多页任务 = 多张 PNG**，可翻页查看；**双面任务每页带「正面 / 背面」角标**（页序：纸1正 → 纸1反 → 纸2正 → 纸2反）；
5. **导出 PDF**：完成的任务点「**导出 PDF**」，全部页合成一个 A4 PDF（横图自动转横向页、等比适配居中）；导出一次后缓存复用，点「**下载 PDF**」直接下载。

### 3. 发现与手动添加

- **自动发现（推荐）**：扫描页点「扫描网络」，基于 mDNS `_uscan._tcp`（与打印机发现同通道）；
- **手动添加**：已知扫描仪地址时填写 `http://IP:端口`（eSCL 常见端口 **80 / 443 / 8080**，具体以打印机网络配置页为准），点「添加」——Host 会先做一次 eSCL ScannerStatus 探活，失败会给出原因。

### 4. 排查要点

| 检查项 | 处理 |
|---|---|
| 扫描仪未发现 | ① 确认一体机支持 AirScan/eSCL（AirPrint 认证 MFP 普遍支持）② 与 Host 同网段、防火墙放行 mDNS（5353/UDP）③ 部分路由器禁用组播 → 改用**手动添加** |
| 任务一直「扫描中」 | 设备忙碌（面板正在扫描 / 卡纸 / 待机唤醒慢）→ 取页总超时 **30 秒**，无进展的任务会自动置为失败；释放设备后重新扫描 |
| 图像 404 | 任务已被删除清理（完成页图先下载再删任务） |
| 「导出 PDF」报错 | 仅**已完成**任务可导出（进行中/取消/失败状态会提示原因）；图像页被手动删除也会报错——重新扫描后再导出 |

### 5. 如实声明

- 扫描输出为 **PNG 图像页**（多页任务 = 多张 PNG）；完成的任务可**按需导出 PDF**（A4 合成，v0.3.3+）。PDF 为本地合成（pdf-lib 嵌入 PNG，不重新编码），**不含可选文本层/OCR**——需要可检索文本请使用专用 OCR 工具后处理。
- **双面扫描（v0.4.1）**：通过 eSCL ScannerCapabilities 探测设备双面能力（三态），请求携带 `<scan:Duplex>true</scan:Duplex>`；仅送稿器（Feeder）有效，平板 + 双面会被拒绝（400）。手动添加的扫描仪在添加时即探测双面能力并持久化。
- 与打印侧同一原则：**不同扫描仪能力不同**（分辨率档位、色彩模式、平板/送稿器、双面），扫描页**只显示实际探测到的能力与参数**，不虚构选项。

### 6. 开发 / 测试环境说明

Virtual eSCL Scanner（开发/测试工具）监听 **:3065**，内置 `vscan-flatbed`（平板单页）与 `vscan-adf`（送稿器多页 + 双面）两个虚拟档案，可在无实体扫描仪的 CI/开发环境中验证扫描全链路（自动化自测场景 `escl-full-flow` + `scan-pdf-export` + `escl-duplex`），**非产品功能**。

## 六、故障排查

### 1. 找不到 Host

| 检查项 | 处理 |
|---|---|
| Host 是否启动 | Host 设备上访问 `http://localhost:3001/` 确认控制台可打开 |
| 是否同一局域网 | Client 与 Host 必须在同一网段（同一 Wi-Fi / 同一交换机） |
| 路由器开了 AP 隔离 | 关闭 Wi-Fi 的「客户端隔离/AP Isolation」 |
| 自动发现失效 | 在 Client「发现主机」页**手动添加** Host 的 `IP:端口`（默认 3001）；Host IP 在其「概览」页查看 |
| 防火墙拦截 | Host 设备放行 3001（REST）与 3002（WebSocket）端口；Windows 首次启动会弹防火墙授权，请允许 |

### 2. 找不到打印机

| 检查项 | 处理 |
|---|---|
| 打印机未共享 | Host「打印机」页打开该打印机的**共享开关** |
| mDNS 扫描无结果 | ① 确认打印机支持网络 IPP（IPP Everywhere/AirPrint 机型）② 打印机与 Host 在同一网段 ③ 部分路由器禁用组播，改用**手动 URI**（`ipp://打印机IP/ipp/print`，地址在打印机面板或其打印的网络配置页上） |
| CUPS/Windows 后端不可用 | 「打印后端」页查看原因：Linux/macOS 需 CUPS 服务运行；Windows 后端只在 Windows 宿主可用 |
| 系统打印机不在列表 | Host 重启或点「刷新状态」重新枚举（`lpstat` / `Get-Printer`） |

### 3. 打印机显示离线

- 打印机面板确认电源与网络（Wi-Fi 指示灯）；
- IPP 直连打印机：点「刷新能力」触发一次 Get-Printer-Attributes 探测，观察是否恢复；
- USB 共享打印机：在 Host 设备上打印测试页确认系统层面正常；
- 打印机深度休眠：面板按键唤醒后再探测；
- 仍离线 → 重启打印机与 Host。

### 4. 无法读取某项能力（显示 UNKNOWN）

**这是预期行为，不是故障。** 该设备/驱动未通过标准协议暴露此项能力。打印不受影响——参数由设备驱动最终裁决。可以：
- 点「刷新能力」重试探测；
- 查看能力报告的「来源探测」详情（哪个协议尝试了、返回什么、失败原因）。

### 5. 无法读取墨量 / 碳粉

- **IPP 直连**：部分机型不返回 `marker-levels`（或返回非精确值）→ 耗材显示 UNKNOWN 或不显示，**不会显示虚假数值**；
- **SNMP community 不匹配**：企业级打印机（Ricoh / Kyocera / KM / Xerox 等）常将 SNMP community 改为非默认值 —— 在 Web 控制台「设备配对」页的「SNMP 探测设置」中填入打印机实际的 community 字符串（默认 `public`），再到打印机页点「刷新能力」；
- **SNMP 未开启**：新型号固件可能默认关闭 SNMP，需在打印机管理页面（网页管理台）开启 SNMP（v1/v2c）；
- **PJL 探测（v0.4.2 兜底）**：IPP/SNMP 均读不到耗材时，可在「设备配对」页启用「PJL 探测设置（RAW 9100）」（默认关闭）——消费级 Brother/HP 机型常支持 9100 双向回读；探测失败（如端口不通/响应非 PJL）只记 `VENDOR_API` 来源探测记录，不影响其它能力与打印；
- 消费级入门机型可能仅支持厂商 App 读取墨量（私有协议），标准协议读取不到属于设备限制。

### 6. 打印失败

1. 队列页点开失败任务，查看**时间线中的失败原因**（如 `ipp 提交失败：printer-unreachable` / `lp 提交失败：…`）；
2. 常见原因对照：
   - `printer-offline / unreachable` → 打印机网络问题（见第 3 条）
   - `media-needed` → 打印机缺纸
   - `job-canceled` → 打印机端取消（面板操作）
   - Windows `PrintTo` 失败 → 确认系统 PDF 关联应用可用（如 Edge）
3. 修复后点「重试」。

### 7. 任务卡住（长时间无进度）

- 先「取消」再重新提交；
- 检查打印机面板（卡纸/缺纸/墨尽提示），处理后多数会**自动续打**；
- 查看打印机状态是否离线（离线时任务等待恢复）；
- 仍卡住 → 重启 Host（任务队列落盘，重启后自动恢复并续打）。

### 8. 网络问题

- **WebSocket 断开**：顶栏连接徽标有灰点 → 系统自动降级为 4 秒轮询，功能不断，恢复后自动升级为实时推送；
- **网关/反向代理环境**：跨端口 API 需要网关支持（参考 `deploy/Caddyfile.example` 的 `XTransformPort` 机制）；直连场景无此要求；
- **打印内容传输慢**：大 PDF 上传耗时取决于 Wi-Fi 质量，任务页会显示提交进度。

### 9. 控制台鉴权（v0.4.0）

| 症状 | 处理 |
|---|---|
| 控制台弹出「控制台已锁定」 | 正常行为：Host 已启用管理面访问令牌。向 Host 管理员索取令牌，输入后本端自动保存 |
| 令牌遗忘 / 所有端被锁 | 在 Host 本机读取数据目录 `console-token.txt`（默认 `data/mock-printer/`，打包产物为程序同目录 data 下），或通过 shell 执行 `cat <数据目录>/console-token.txt` 恢复 |
| 重生成后其他浏览器被锁 | 预期行为：旧令牌立即失效。被锁端在解锁界面输入新令牌即可（或清除该端 localStorage 的 `ops.consoleToken` 后输入新值） |
| API 调用返回 401 `console_auth_required` | 携带令牌重试：`x-ops-console-token` 头 / `Authorization: Bearer` / `?opsToken=`（三通道等价） |
| 图片 / PDF 下载链接失效 | 下载 URL 自动追加 `opsToken=`；若手动构造 URL，需自行带上该参数（`<img>` 标签无法携带请求头） |
| 想关闭鉴权但令牌丢了 | 先从 `console-token.txt` 恢复令牌 → 解锁 → 「设备配对」页「控制台访问控制」→ 关闭（或 `POST /api/console/disable` 携带令牌） |

## 附录：端口与数据

| 端口 | 用途 |
|---|---|
| 3001 | Host REST API + 内嵌 Web 控制台（浏览器访问 `http://<Host-IP>:3001/`） |
| 3002 | WebSocket 实时推送（自动连接，无需配置） |
| 5353/UDP | mDNS 发现（打印机/扫描仪扫描与自通告） |

> 开发/测试端口（非产品功能）：`:3061`（Virtual IPP 明文）/ `:3063`（Virtual IPP TLS）/ `:3065`（Virtual eSCL Scanner），见对应章节。

数据目录（Host 侧，落盘可审计）：打印机注册表 / 设置 / 已配对设备 / 事件日志（`events.jsonl`）/ 每任务工件（`document.pdf` + `job.json` + `result.json`）/ 扫描设备与扫描任务（`scan-devices.json` + `scan-jobs/{id}/job.json` + `scan-jobs/{id}/page-{n}.png`）。
